🔴 Bloquants Critiques

Ces problèmes doivent être résolus avant tout déploiement en production.

BC-1 Absence de Circuit Breaker sur les appels HTTP inter-services
*/src/clients/NotificationClient.ts (auth, shipment, tracking)

Tous les appels HTTP vers les services aval sont effectués sans circuit breaker. Un notification-service dégradé bloquera tous les appelants pendant 5 s, épuisant la boucle événementielle Node.js et provoquant une panne en cascade.

→ Correction
const breaker = new CircuitBreaker(fetchWithTimeout, {
  timeout: 5000,
  errorThresholdPercentage: 50,
  resetTimeout: 30000,
});
BC-2 Aucun Index Mongoose Défini dans le Code
auth-service/src/infrastructure/db/UserModel.ts · tous les *Model.ts

Seuls des index simples unique: true existent. Les requêtes filtrant par tenantId effectuent des scans complets de la collection — goulot d'étranglement à 10 k documents, panne à 100 k.

→ Correction
UserSchema.index({ tenantId: 1, email: 1 });          // index composé
UserSchema.index({ tenantId: 1, role: 1 });
RevokedTokenSchema.index({ expiresAt: 1 }, { expireAfterSeconds: 0 }); // TTL
BC-3 Absence de File de Messages — Notifications Perdues en cas d'Échec
shipment-service/src/clients/NotificationClient.ts · toutes les implémentations NotificationClient

Les erreurs fire-and-forget sont absorbées silencieusement (simple console.error). Aucune file morte, aucun réessai, aucune visibilité sur les notifications perdues. Aucune intégration BullMQ, RabbitMQ ou Redis Streams.

→ Correction

Introduire une file BullMQ dans notification-service. Les producteurs poussent des jobs ; le worker retente avec backoff exponentiel (3 tentatives, 2×, max 30 s).

BC-4 Aucun Test de Charge — Capacités Inconnues
Absent : répertoire load-tests/

Aucun script k6, Artillery ou Locust dans le dépôt. Plafonds de débit, latence p99 sous charge et seuils de saturation CPU/mémoire totalement inconnus. Les SLOs ne peuvent pas être validés.

→ Correction

Créer load-tests/ avec des scripts k6 couvrant : connexion, création d'expédition, mise à jour GPS.

🟠 Problèmes à Risque Élevé

RE-1 Absence de Versionnage de l'API (préfixe /v1)

Toutes les routes sont montées à la racine. Tout changement incompatible nécessite une bascule coordonnée de tous les clients sans fenêtre de dépréciation.

→ Correction

Préfixer toutes les routes avec /v1 dans api-gateway/src/proxy/proxyRouter.ts et mettre à jour docs/openapi.yaml.

RE-2 Absence de Réessai avec Backoff Exponentiel
shipment-service/src/utils/fetchWithTimeout.ts

fetchWithTimeout lève une exception dès le premier échec. Les erreurs transitoires provoquent des échecs permanents au lieu de se résoudre automatiquement.

→ Correction
// 3 tentatives, base 500 ms, multiplicateur 2×
async function retryWithBackoff(fn, retries = 3, base = 500) {
  for (let i = 0; i <= retries; i++) {
    try { return await fn(); }
    catch (e) {
      if (i === retries) throw e;
      await delay(base * 2 ** i);
    }
  }
}
RE-3 tracking-service NotificationClient Utilise fetch() Sans Timeout
tracking-service/src/clients/NotificationClient.ts

Contrairement aux autres services, le tracking-service utilise le fetch() natif sans AbortController. Un notification-service lent peut bloquer indéfiniment un gestionnaire WebSocket.

→ Correction

Remplacer par fetchWithTimeout(url, options, 5_000) — déjà implémenté dans shipment-service/src/utils/fetchWithTimeout.ts.

RE-4 Absence d'En-tête Content Security Policy (CSP)
nginx/nginx.conf · api-gateway/src/server.ts

Ni Nginx ni Helmet ne définissent un en-tête Content-Security-Policy. Sans CSP, une attaque XSS réussie ne rencontre aucune atténuation au niveau du navigateur.

→ Correction (Nginx)
add_header Content-Security-Policy
  "default-src 'self'; script-src 'self'; object-src 'none';" always;
RE-5 Les Secrets Docker ne Sont pas Utilisés en Production
docker-compose.prod.yml

Les secrets sont passés sous forme de variables d'environnement en clair. Tout docker inspect ou listing de processus expose toutes les valeurs secrètes.

RE-6 Absence d'ESLint et de Seuil de Couverture dans la CI
.github/workflows/ci.yml

La CI exécute tests, typecheck, build Docker et npm audit — sans lint et sans seuil de couverture. Les régressions de style et les baisses de couverture passent inaperçues.

→ Correction

Ajouter npm run lint et --coverageThreshold='{"global":{"lines":70}}' à la commande de test.

🟢 Points Forts de l'Architecture

Ces éléments sont de qualité production et doivent servir d'implémentations de référence.

F-1 TLSv1.2+, HSTS Preload, Suite de Chiffrement Moderne

nginx/nginx.conf impose TLSv1.2+, HSTS 2 ans avec preload, tickets de session désactivés. Conforme au profil Mozilla "Intermediate".

F-2 Rate Limiting Multi-couches

Zones Nginx (10 req/min auth, 100 général) + express-rate-limit adossé à Redis. Résiste aux redémarrages sans perte d'état des compteurs.

F-3 bcrypt 12 Rounds, Asynchrone, Value Object

Password.ts — bcrypt 12 rounds (~250 ms/hachage), pattern value-object garantit que les mots de passe ne sont jamais accidentellement loggés.

F-4 Liste Noire de Révocation de Tokens

LogoutUseCase + IRevokedTokenRepository avec nettoyage TTL. JWT sans état avec révocation avec état — le meilleur des deux approches.

F-5 Arrêt Gracieux sur les 7 Services

SIGTERM/SIGINT, drainage via server.close(), fermeture MongoDB, kill forcé après 10 s. Prévient toute perte de données lors des redémarrages.

F-6 Stack Complète Prometheus + Grafana + Alertmanager

6 règles d'alerte, dashboard 8 panneaux, alertes email, rétention 15 jours.

F-7 Logs Pino Structurés + X-Request-ID via AsyncLocalStorage

JSON en production, lisible en dev. IDs propagés depuis Nginx jusqu'au dernier service, inclus dans chaque ligne de log.

F-8 Documentation OpenAPI 3.0

docs/openapi.yaml — 30+ endpoints, tous les 7 services, schémas requête/réponse, sécurité Bearer.

F-9 API Gateway à Charge Équilibrée (2 instances)

Nginx least_conn, max_fails=3 fail_timeout=30s, pool keepalive 32 connexions.

F-10 Health Checks sur Chaque Service

GET /health retourne { status, db, uptime } avec HTTP 200/503. Docker wget --spider, 15 s, 3 tentatives.
