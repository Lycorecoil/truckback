2. Sécurité — Couches d'authentification

2.1 Flux d'une requête

Client → [1] Rate Limit — 429 si quota dépassé (100 req/min par défaut)
→ [2] authMiddleware — vérifie JWT HS256, injecte x-user-id / x-user-role / x-tenant-id
→ [3] requireRoles() — vérifie que le rôle est autorisé sur ce préfixe
→ [4] Proxy → Service — transmet la requête avec les headers JWT
→ [5] RBAC fin (controller) — chaque route vérifie à nouveau le rôle précis
→ Client

Routes publiques (sans JWT) : POST /auth/signup et POST /auth/login

2.2 Headers injectés par le gateway

HeaderSource dans le JWTExemple
x-user-idpayload.subuuid-1234-abcd
x-user-rolepayload.roleTRANSPORTER
x-tenant-idpayload.tenantIdtenant-xyz

Les services en aval font confiance à ces headers sans re-vérifier le JWT. Ils sont impossibles à forger depuis le client car posés uniquement après vérification de la signature.

5. Workflows par acteur

5.1 ADMIN

Supervision globale de la plateforme. Accès total en lecture/écriture sur tous les services.

1POST /auth/signup — Créer son compte { role: "ADMIN", tenantId: "...", email, password }
2POST /auth/login — Récupérer le JWT → à mettre dans Authorization: Bearer <token>
3GET /fleet/trucks — Voir tous les camions de la plateforme
4GET /fleet/drivers — Voir tous les chauffeurs
5GET /shipments — Voir toutes les expéditions (tous statuts)
6PUT /shipments/:id — Modifier une expédition (seul rôle autorisé)
7GET /tracking/truck/:truckId — Suivre n'importe quel camion

5.2 COMPANY (Expéditeur)

Crée des annonces de transport, suit ses expéditions, peut annuler.

1POST /auth/signup — { role: "COMPANY", tenantId: "mon-org-id", email, password }
2POST /auth/login — Récupérer le JWT
3POST /shipments — Créer une annonce
{
  "poids": 3000,
  "villeDepart": "Cotonou",
  "paysDepart": "Bénin",
  "villeArrivee": "Lagos",
  "paysArrivee": "Nigeria",
  "description": "Matériaux de construction"
}
→ companyId injecté automatiquement depuis le JWT
→ Statut = PENDING
→ Email automatique aux transporteurs compatibles
4GET /shipments/search?poids=3000&villeDepart=Cotonou&paysDepart=Bénin — Voir les camions disponibles
5GET /shipments — Voir uniquement ses propres expéditions (isolation automatique)
6GET /shipments/:id — Détail d'une expédition
7GET /tracking/shipment/:shipmentId — Suivre sa marchandise en temps réel
8DELETE /shipments/:id — Annuler (→ statut CANCELLED + email auto au transporteur si déjà assigné)

5.3 TRANSPORTER (Transporteur)

Gère sa flotte (camions + chauffeurs), accepte des missions d'expédition.

Phase 1 — Inscription et configuration

1POST /auth/signup — { role: "TRANSPORTER", tenantId: "mon-org-id", email, password }
2POST /auth/login — Récupérer le JWT
3POST /fleet/trucks — Ajouter un camion
{
  "immatriculation": "BN-1234-AB",
  "marque": "Mercedes",
  "modele": "Actros",
  "capacite": 5000,
  "typeVehicule": "BENNE",
  "villeDepart": "Cotonou",
  "paysDepart": "Bénin"
}
→ tenantId injecté automatiquement depuis le JWT
4GET /fleet/trucks — Voir uniquement ses propres camions
5POST /auth/driver/create — Créer un compte chauffeur
{
  "email": "chauffeur@example.com",
  "password": "motdepasse123",
  "tenantId": "mon-org-id",
  "transporterId": "mon-user-id",
  "telephone": "+22960000000"
}
→ Email + SMS de bienvenue envoyés automatiquement avec les identifiants + lien de téléchargement
6GET /fleet/drivers — Voir uniquement ses propres chauffeurs
7POST /fleet/trucks/assign-driver — Assigner un chauffeur à un camion
{ "truckId": "...", "driverId": "..." }

Phase 2 — Gestion des missions

8GET /shipments — Voir les expéditions qui lui sont assignées (après acceptation)
9POST /shipments/:id/accept — Accepter une mission
{ "truckId": "...", "driverId": "..." }
→ transporterId injecté depuis le JWT (impossible de forger)
→ Lock atomique MongoDB — seul le premier transporteur à accepter réussit
→ Statut = ACCEPTED
10GET /tracking/truck/:truckId — Suivre son chauffeur en temps réel

5.4 DRIVER (Chauffeur)

Compte créé par le transporteur. Reçoit ses identifiants par email/SMS. Exécute la livraison.

Note : le chauffeur ne crée pas son propre compte. Il reçoit automatiquement un email et un SMS contenant ses identifiants et le lien de téléchargement de l'application mobile.

1POST /auth/login — Se connecter avec les identifiants reçus par email
2GET /shipments/:id — Voir le détail de sa mission (adresse, poids, description)
3POST /shipments/:id/start — Démarrer la livraison au moment du départ
→ Statut = IN_PROGRESS
4POST /tracking — Envoyer la position GPS en continu (toutes les N secondes)
{
  "truckId": "...",
  "shipmentId": "...",
  "latitude": 6.3703,
  "longitude": 2.3912,
  "vitesse": 75
}
→ Diffusé en temps réel via WebSocket ws://localhost:3007 à tous les clients connectés
→ Si silence > 30 min : alerte email automatique à l'expéditeur
5GET /tracking/truck/:truckId — Vérifier sa propre position si besoin
6POST /shipments/:id/deliver — Confirmer la livraison à destination
→ Statut = DELIVERED
